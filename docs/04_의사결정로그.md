# 04. 의사결정 로그 & 오픈 이슈

> 방향이 바뀐 이력과 그 이유를 기록한다. 새 결정이 내려지면 이 파일에 추가한다. 오픈 이슈는 아직 결정되지 않은 것 — 임의로 확정하지 말고 사용자와 논의한다.

## 의사결정 로그

### D-01 (2026.8) 사업 본체 = 직거래 플랫폼 [확정]
- 초기 논의: "AI 정보 제공 + 가격 공개 웨딩 플랫폼" 구상에서 출발. 업계 권력 구조(폐쇄형 소개경제) 분석.
- 중간 산출물에서 Claude가 "경쟁(웨딩북 등) 회피 → AI 계약검토 단독 도구('웨딩체크')"로 축소 제안 → **사용자 반려** ("내가 원하는 방향의 비즈니스가 아니야").
- 확정: 본체는 **투명 가격 직거래 플랫폼**. 계약 검토·AI 플래너는 플랫폼 기능 중 일부(매력 기능). 교훈: 틈새 축소 제안 금지, 정면 승부 전제 유지.

### D-02 (2026.8) 사업 규모 = 투자 유치·경쟁 진출형 [확정]
- 1인 사이드프로젝트형 아님. 시드 10~15억 유치 전제, 팀 빌딩 포함 기획.

### D-03 (2026.8) 수익 모델 원칙 [확정]
- 업체 광고·제휴·리베이트 수익 금지(차별성의 근간). 거래 수수료 5~8%(업체 부담) + 소비자 멤버십 주력. 컴플라이언스 SaaS·플래너 매칭·금융 제휴·데이터는 후속.
- 사용자 원 코멘트: "수익 모델은 재정의와 설정이 필요" → 상기안으로 기획서에 반영됨. 세부 요율은 오픈 이슈(O-02).

### D-04 (2026.8) 진입 순서 = 콜드스타트 4단계 [확정]
- P1 수요 선확보(공급 불필요 기능) → P2 절박한 공급(비수기·평일·지방, 실장 영업) → P3 거래 표준(전자계약·에스크로·검증후기·플래너 마켓) → P4 확장.
- 근거: 양면 시장 닭-달걀 + 소개망 보복 리스크 회피.

### D-05 (2026.8) 가칭 확정(잠정)
- 서비스: 웨딩클리어(WeddingClear), AI: '클리어'. 정식 네이밍·상표 검토는 오픈 이슈(O-01).

### D-06 (2026.8) 기술 스택 기본값
- Next.js+TS+Supabase+Claude API+토스+Vercel. 03_기술개발_컨텍스트.md 참조.

### D-07 (2026.8) 앱 전략 = 단계적 하이브리드 [확정]
- 1단계: 웹(PWA) 본체 + Capacitor 래핑으로 iOS/Android 출시 (P1 필수 네이티브 기능 = 카메라·푸시·스토어 입점, 전부 플러그인 커버).
- 2단계: 전환 트리거(채팅 UX 한계, 위젯·백그라운드 요구, 앱 리텐션 열세 데이터, P3 생체인증) 충족 시 Expo 병행 — packages/core 로직 재사용.
- 리포 구조: Turborepo+pnpm 모노레포, 로직은 packages/core 격리(전환 대비). 근거·폴더 구조·로컬 환경은 05_앱개발_로컬환경_가이드.md.
- 근거: P1 성패가 SEO 수요 확보에 달려 웹이 본체일 수밖에 없음 + 팀 5~7명 규모에서 코드베이스 2개 유지 비용 회피 + 사용자 Expo 경험으로 전환 리스크 낮음.


### D-08 (2026.8) 폴더 구조 = 단일 Next.js 앱 (saju 스타일) [확정]
- 사용자 기존 프로젝트(saju)와 동일한 단일 앱 구조로 확정 — 모노레포(Turborepo) 안은 폐기.
- 로직 격리 원칙은 유지: 도메인 로직(룰·가격·스키마)은 lib/core에 두고 React/Next import 금지 → Expo 전환 시 패키지로 승격.
- 실제 스캐폴드(weddingclear_scaffold.zip) 생성됨: 라우트 그룹·lib 스텁(ReportSchema, penalty 엔진 골격, supabase 클라이언트)·마이그레이션/시드 자리·CLAUDE.md/AGENTS.md·dev-setup.bat·docs(00~05 사본) 포함.

## 오픈 이슈 (미결정 — 논의 필요)
- **O-01 네이밍·브랜드**: '웨딩클리어'는 가칭. 상표 검색·도메인·네이밍 후보군 작업 필요.
- **O-02 수수료 요율 확정**: 5~8% 범위 내 카테고리별 요율(홀 vs 스드메), 멤버십 가격 A/B 설계.
- **O-03 에스크로 법무**: PG 에스크로 활용 범위, 전자금융업 등록 시점, 예치금 운용 가능 여부 — 법무 자문 필요.
- **O-04 플랫폼 버전 개발명세서**: 미작성. MVP 범위(P1 기능만? P2 공급 어드민 포함?) 결정 필요.
- **O-05 IR 덱**: 투자용 10~15장 덱 미작성.
- **O-06 재무모델 상세**: 3개년 요약만 존재. 월 단위 xlsx 모델 필요.
- **O-07 검증 인터뷰**: 웨딩홀 영업팀장·스드메 대표·프리랜서 플래너·신혼부부 심층 인터뷰 설계·실행 — 30% 수수료율, 컨설팅 경유 매출 비중, 비수기 공실률 등 가설 수치의 1차 검증.
- **O-08 P1 MVP 기능 우선순위**: AI 플래너 6개 세부 기능 중 첫 출시 범위.
- **O-09 팀·공동창업자**: 공급 영업(실장 출신)·AI 엔지니어 확보 계획.
