# 재고 CSV 형식 (S2-05 · F-V-05)

> 업체가 외부 캘린더에서 뽑은 예약 가능 날짜를 `/vendor/inventory` 에서 한 번에 올릴 때 쓴다.
> 파서는 `lib/core/inventory/csv.ts` 이며 형식이 바뀌면 그 파일과 이 문서를 함께 고친다.

## 형식

첫 줄은 **헤더**다. 열 순서는 자유이며 이름으로 찾는다.

```csv
date,time,capacity,product_id
2026-10-10,11:00,1,
2026-10-10,14:00,1,
2026-10-11,11:00,2,
```

| 열 | 필수 | 형식 | 설명 |
|---|---|---|---|
| `date` | 필수 | `YYYY-MM-DD` | 예약 가능 날짜 |
| `time` | 필수 | `HH:MM` (24시간) | 시작 시각. 초는 쓰지 않는다 |
| `capacity` | 필수 | 1 이상 정수 | 그 시각에 받을 수 있는 건수. **0은 쓸 수 없다** — 휴무는 화면의 '블록'으로 처리한다 |
| `product_id` | 선택 | uuid | 상품별 재고일 때만 적는다. 비우면 업체 전체 재고 |

- 빈 줄과 BOM(엑셀이 붙이는 `﻿`)은 무시한다.
- 따옴표 안의 쉼표는 값의 일부로 본다. 엑셀의 `""` 이스케이프도 처리한다.
- `remaining`(잔여)은 CSV 로 받지 않는다. 등록 시점에는 항상 `capacity` 와 같고,
  예약이 붙을 때만 줄어든다(4단계).

## 오류 처리 — 부분 반영하지 않는다

**한 행이라도 형식이 틀리면 아무것도 저장하지 않고 행별 오류를 돌려준다.**

절반만 저장하면 업체는 어느 날짜가 반영됐는지 모른 채 파일을 고쳐 다시 올리게 되고,
그 재시도가 **중복 등록**(같은 자리 두 번)이나 **누락**(고친 행만 올림)을 만든다.
재고는 예약 가능 여부와 직결되므로 "일부 성공"이 가장 나쁜 상태다.

응답 예시(422):

```json
{
  "ok": false,
  "error": {
    "code": "VENDOR_SLOT_CSV_INVALID",
    "message": "CSV 를 읽지 못했습니다.",
    "details": [
      { "line": 3, "message": "date: 날짜는 YYYY-MM-DD 형식으로 입력해 주세요." },
      { "line": 5, "message": "capacity: 정원은 1 이상이어야 합니다. 휴무는 '막음'으로 표시하세요." }
    ]
  }
}
```

`line` 은 **사람이 세는 줄 번호**(1부터, 헤더 포함)다. 파일을 열어 그 줄을 바로 찾을 수 있어야 한다.

## 한도

- 한 번에 **2000개**까지(`SLOT_BULK_MAX`). 실수로 몇 년치를 만드는 사고를 막는다.
- 같은 업체·상품·날짜·시각의 슬롯은 **하나뿐**이다. 요청 안에서 중복이면 422,
  이미 등록돼 있으면 409 다. DB 에도 UNIQUE 인덱스가 걸려 있어 어느 경로로도 통과하지 못한다.

## 파싱에 외부 라이브러리를 쓰지 않는 이유

필요한 것은 따옴표와 줄바꿈을 다루는 최소한의 파서뿐이다. 그 정도는 30줄로 만들어
테스트로 고정하는 편이 의존성을 하나 더 지는 것보다 낫다(CLAUDE.md — 새 의존성은 보고 대상).
