## 한 장 요약

**만들기로 한 것은 거의 다 만들었다. 만든 것이 전부 돌아가는 것은 아니다.**

- 소비자·업체·운영자·플래너 **네 면**이 다 서 있다. 화면 **101개**, API **133개**, DB 표 **111개**.
- 한 거래가 **문의 → 견적 → 예약 → 계약 → 서명 → 결제 → 정산**까지 **실제 브라우저로 끝까지 간다**
  (자동 검사가 매번 28단계를 민다). **그 사슬을 이은 것이 바로 직전 작업이다** — 그전까지는
  계약 발행에서 끊겨 있었고, 화면은 전부 정상이라 **아무 검사에도 걸리지 않았다.**
- 차별성(투명 가격)은 **말이 아니라 DB 제약으로** 서 있다 — 추가금을 미리 안 적으면 상품이
  **게시 자체가 안 되고**, 견적은 **상한을 넘으면 저장이 거부된다**. [나](#나-차별화-기능--코드가-강제하는-것) 절.
- **남은 일은 세 갈래다.** ① 쇼핑몰다움과 일정 연결(11개 작업, 이번에 등록했다) ② 디자인 다듬기
  ③ **코난님이 계약하거나 값을 정해야 움직이는 것 18가지**(계약·발급 6 · 정해야 할 값 10 · 조사 2)
  — **이쪽은 개발로 못 푼다.**

**지금 오픈할 수 있는가 — 아니다.** 막는 것은 기능이 아니라 **외부 계약과 미정 파라미터**다.
결제사 실계약·법무 조항·수수료 요율이 없으면 돈이 도는 부분이 스텁(껍데기)으로 남는다.

## [가] 한 것 — 기능 단위

> 각 줄은 **지금 화면에서 실제로 되는 일**이다. "코드가 있다" 가 아니라 "눌러서 된다" 를 기준으로
> 적었다. 반쪽인 것은 여기 넣지 않고 [라](#라-지금-안-되는-것) 절로 보냈다.

### 소비자 — 예비부부가 쓰는 것

| 무엇 | 지금 되는 일 |
|---|---|
| 가입·온보딩 | 이메일로 가입하고 6문항(예식일·지역·예산·하객·취향·진행단계)에 답하면 **체크리스트와 예산 초안이 자동으로 생긴다** |
| 배우자 연동 | 초대 코드로 배우자를 묶으면 **같은 데이터를 함께 본다**. 누가 바꿨는지 기록된다 |
| 업체 탐색 | 지역·예산·하객수·날짜·취향으로 거른다. **정렬 기준을 화면이 항상 말한다**("가격 낮은 순") |
| 조건 검색 | "0월 0일 강남 300인" 처럼 말로 써도 조건을 알아듣고, **알아들은 것을 칩으로 보여 주고 지울 수 있다** |
| 업체 상세 | 총액·포함 항목·**추가금 사전표**를 한 화면에서 본다. 예식일을 고르면 그날 가격이 나온다 |
| 찜·장바구니 | 상품을 담는다. **조합을 최대 5개까지 따로** 만들어 총액을 비교한다. 예산 대비 여유·초과를 함께 본다 |
| 문의 보내기 | **한 번에 최대 5개 업체**에 같은 조건으로 보낸다. 업체마다 답이 왔는지·거절인지·기한이 언제인지 본다 |
| 견적 비교 | 받은 견적 2~5개를 **같은 항목 축으로 맞춰 나란히** 놓는다 |
| 채팅·Q&A | 업체와 1:1 대화. 업체별 공개 Q&A 게시판 |
| 상담·탐방 예약 | 업체가 연 시간대에서 고르고 업체가 승인하면 확정. **방문·탐방은 보증금이 선행**이며 이행하면 돌려받는다 |
| 계약·서명 | 예약에서 계약이 발행되고 **고객·업체가 각각 서명**한다. 정본 해시가 남는다 |
| 분할 결제 | 계약 1건을 **회차로 나눠** 낸다. 회차마다 조건·기한·금액을 **결제 전에 고지하고 동의를 기록**한다 |
| 해지·환불 | 해지를 요청하면 위약금이 **계산되어** 나온다. 동의와 귀책을 **따로** 낸다 |
| 안전거래 | 잔금을 예치하고 이행 확인 뒤 푼다(**실예치는 아직 껍데기** — [라](#라-지금-안-되는-것)) |
| 계약서 검토 | 계약서를 올리면 **위험 조항을 등급별로** 짚고 근거와 협상 문구를 준다. **원문은 24시간 안에 지운다** |
| 위약금 계산기 | 계약금·총액·예식일·취소 시점을 넣으면 **기준 대비 초과분**을 계산한다. **로그인 없이 쓴다** |
| 예산 | 카테고리별 배분과 실지출. 계약이 잡히면 자동 반영 |
| 체크리스트 | 예식일 역산으로 할 일이 자동 생성된다. **"이걸 먼저 해야 저게 됩니다" 를 표시**하고 표현 4가지로 본다 |
| AI 플래너 | 대화로 묻는다. 우리 데이터를 실제로 조회해 답한다. **결제·서명은 대신 하지 않고 화면으로 보낸다** |
| 하객·좌석 | 명단, 초대 링크(하객마다 다른 주소), 참석 응답 집계, 좌석 초안 |
| 후기 | **거래한 사람만** 쓴다. 항목별 평점 + 실지출 금액 공개 선택 |
| 커뮤니티 | 자유·경험담·Q&A 게시판. 업체는 **태그로만** 언급하고 **미검증 경험담** 라벨이 붙는다 |
| 쿠폰 | 보유 쿠폰과 **왜 못 쓰는지**까지 본다. 결제 시 할인 전·할인액·할인 후를 함께 본다 |
| 멤버십 | 가입·해지 예약. **지금 실제로 갈리는 것은 AI 대화 횟수 하나**이며 화면이 그렇게 적는다 |
| 공유 | 검토 결과·비교표를 **만료되는 링크**로 넘긴다. 받는 사람은 로그인이 필요 없다 |
| 가이드 | 가이드·용어사전·가격 리포트. 글에서 도구로 바로 간다 |

## [나] 차별화 기능 — 코드가 강제하는 것

> **"그렇게 하겠다" 와 "그렇게 안 하면 저장이 안 된다" 는 다르다.** 아래 여섯은 후자다.
> 화면을 고쳐도, 실수로 다른 코드를 써도, **데이터베이스가 거부한다.** 그래서 이것들이
> 광고 없는 투명 가격이라는 약속의 실제 근거다.

| 약속 | 어떻게 강제되나 | 무너뜨리려면 |
|---|---|---|
| **추가금은 미리 다 적는다** | 상품을 고객에게 **게시하는 순간**을 DB 제약이 막는다 — 총액이 0보다 크고, 포함 항목이 1개 이상이고, **추가금 사전 등록이 확정**돼 있어야 `published` 가 된다. 확정 전 상품은 고객 눈에 **존재하지 않는다** | 마이그레이션을 새로 써서 제약을 지워야 한다 |
| **견적은 상한을 넘을 수 없다** | 견적 행에 `총액 ≤ 상한` 제약이 걸려 있다. 상한은 **업체가 등록한 가격과 룰로 서버가 계산**한다. 업체가 화면에서 더 큰 숫자를 보내면 **저장이 거부된다** | 같음 |
| **견적은 표준 폼으로만 온다** | 견적 **항목을 서버가 채운다.** 클라이언트가 무엇을 보내든 무시된다 — 자유 텍스트를 항목 자리에 넣을 **방법이 없다**. 자유 텍스트는 메모 칸 하나에만 허용된다 | 서버 로직을 바꿔야 한다 |
| **후기를 대가로 쿠폰을 주지 않는다** | 쿠폰의 발행 조건이 **다섯 값으로 고정**돼 있다(계약 완료 · 첫 구매 · 기간 행사 · 재구매 · 수동 지급). **리뷰·후기·평점을 뜻하는 값이 그 집합에 없다.** 자유 입력이 아니라서 적을 칸 자체가 없다 | 제약 값 집합을 넓혀야 한다 |
| **광고가 순위를 바꾸지 않는다** | 광고·유료 노출·후원 순위를 담을 **컬럼이 스키마에 아예 없다.** 그리고 목록 API 는 **적용된 정렬 기준 코드를 응답에 반드시 싣고** 화면이 배지로 보여 준다 — "유료 노출 없음" 을 말이 아니라 **화면으로 증명**한다. 근거를 댈 수 없는 '추천순' 은 **의도적으로 만들지 않았다** | 컬럼을 새로 만들고 정렬 로직과 배지를 함께 고쳐야 한다 |
| **후기는 거래한 사람만 쓴다** | 화면 제한이 아니라 **행 수준 보안 정책**이다. 후기를 넣을 때 DB 가 **그 커플·그 업체의 확정된 예약이 실제로 있는지** 직접 확인한다. 예약이 없으면 **어떤 경로로도** 후기가 들어가지 않는다 | 정책을 바꿔야 한다 |

> **추가로 — AI 결과에 대한 안전장치.** 계약서 검토는 ① 결과를 **형식 검증**하고 ② 인용한 조항이
> **원문에 실제로 있는지 글자로 대조**해 없으면 그 항목을 **버린다**(근거 없는 위험 판정을 만들지
> 않는다) ③ 부분 결과를 **보여 주지 않는다** ④ 모든 화면에 **"법률 자문이 아님" 을 상시 노출**한다.
> 위약금·총액·수수료 같은 **돈 계산에는 AI 를 쓰지 않는다** — 순수 계산 함수이며 단위 테스트가 지킨다.
>
> **그리고 개인정보.** 계약서 원문은 **분석 후 24시간 안에 삭제**되고, AI 에 보내기 **전에**
> 이름·연락처·주민번호·주소·계좌·사업자번호를 **가린다**. 가리기에 실패하면 **AI 를 부르지 않는다.**
> 원문·저장 경로·복원표는 **어떤 로그에도 남기지 않는다.**

### 1. 쇼핑몰다움 — 6개 작업 (`C-2`)

> **카테고리 정리가 실제로 만든 것 (2026-09-19).** 준비 항목에서 "어디서 사는지" 를 물으면
> 이제 **세 가지 다른 답**이 나온다 — ① 파는 곳이 있다(웨딩홀·스드메) ② **여기서 파는 것은**

>
> **업체 카테고리를 늘리는 일은 아직 안 했다** — 일부러다. 먼저 늘리면 **고를 수는 있는데**

## [라] 지금 안 되는 것

> **만들었는데 안 도는 것과 반쪽인 것.** 이 절이 이 문서에서 가장 중요하다 —
> [가] 절만 읽으면 실제보다 좋아 보인다.

### 만들었는데 실제로는 안 도는 것

| 무엇 | 실제 상태 |
|---|---|
| **할 일 기한 알림** | **나가지 않는다.** 알림 배치가 **체크리스트를 아예 읽지 않는다** — 예식일 기준 8번(D-100·60·30·14·7·3·1·0)만 보내고 내용은 "예식일까지 N일 남았어요" 가 전부다 |
| **찜한 상품 가격 변동 알림** | **나가지 않는다.** 알림 문구는 만들어져 있는데 **그것을 보낼 배치가 없다** |
| **알림에서 화면으로 이동** | **안 된다.** 알림에 링크가 없다. 알림함에서 눌러도 아무 데도 안 간다 |
| **체크리스트 → 상품·가이드** | **링크가 0개다.** 할 일은 보여 주는데 거기서 나갈 수 없다 |
| **실시간 동기화** | **없다.** 업체가 바꾼 것이 고객 화면에 **바로 반영되지 않는다** — 새로고침해야 한다. 채팅만 예외이고 그것도 폴링이며, **화면이 스스로 "즉시 반영되지 않습니다" 라고 적는다**(거짓말은 하지 않는 상태다) |

### 반쪽인 것 — 구조는 있고 알맹이가 없다

| 무엇 | 무엇이 없나 |
|---|---|
| **참가격 지수** | 화면·계산·큐레이션 도구는 다 있는데 **표본 데이터가 없다.** 가격 리포트 글도 그래서 안 썼다 — 빈 페이지에 제목만 붙이지 않기로 했다 |
| **안전거래(에스크로)** | 스키마·판정·배치는 도는데 **실제 예치는 껍데기**다. 법무 결론과 계약이 선행이다 |
| **표준계약서 조항 문안** | 조항 **자리**는 있고 **문안이 비어 있다.** 법무 결론 전에 문안이 먼저 서지 못하도록 **DB가 막고 있다** |
| **소셜 로그인** | 버튼이 있고 **비활성**이다. 공급자 키 발급이 선행 |
| **알림톡·조직 채널** | 어댑터와 껍데기는 있고 **실제 발송사 계약이 없다** |
| **외부 캘린더 연동** | 구글·네이버 일정 연동 미구현 |
| **가이드 콘텐츠** | 발행된 글이 **1건**이다. CMS·SEO·구조는 다 섰는데 **쓸 사람이 없었다** |
| **커뮤니티** | 화면·정책·모더레이션은 섰는데 **글이 없다.** 그리고 **운영 정책이 미정**이다 |
| **정렬 3종**(후기 점수·예약 가능일·응답 속도) | **일부러 막아 두었다.** 데이터를 가진 업체가 일부뿐이라 켜면 **"잘하는 순" 이 아니라 "등록했는지" 가 순서를 정한다.** 화면이 그 이유를 적는다 |
| **커버리지 측정** | 테스트는 2,803개가 돌지만 **커버리지 수치를 안 재고 있다**(측정 도구 미설치) |
| **E2E 자동화** | 실제 브라우저 검사를 직접 만들어 쓰고 있고 **표준 도구(Playwright)는 아직 없다** |

### 알고 있는 사각지대

> **"있다" · "열린다" · "맞다" · "이어진다" 는 서로 다른 것이고, 이 프로젝트는 그 값을 치르며 배웠다.**
>
> - 화면 **97개가 전부 정상이고** API **1,320건이 전부 맞는** 상태에서 **한 거래가 끝까지 가지 못했다** —
>   계약 발행 버튼이 없었는데, **부를 자리가 없는 API 는 어떤 점검도 통과한다.**
> - **열린 화면이 옛 가격을 말하고 있었다**(서버 조회가 1년짜리 캐시에 굳어 있었다).
> - **열린 화면이 갖춰진 계약 조항을 지우고 있었다**(이름 가리기가 계약서 문구 30개 중 26개를 지웠다).
> - 보안 검사 **15개가 표가 비어 있어서** 통과하고 있었다.
>
> 그래서 지금은 검사가 다섯 축으로 돈다 — **있는가 / 열리는가 / 맞는가 / 이어지는가 / 막는가.**
> 그래도 **"맞는가" 는 여전히 자동으로 못 센다.** 사람이 봐야 한다.

## [마] 외부 의존 — 코난님이 결정하거나 계약해야 하는 것

> **개발로는 못 푼다.** 아래가 정해지지 않으면 해당 부분은 **스텁이거나 아예 안 움직인다.**
> 그리고 이 리포는 **코드가 대신 값을 고르지 않기로** 했다 — 값이 없으면 **명시적으로 실패**한다.
> 조용히 기본값을 쓰면 아무도 정하지 않은 숫자로 돈이 움직이기 때문이다.

### 계약·발급이 필요한 것

| 무엇 | 없으면 | 누구와 |
|---|---|---|
| **소셜 로그인 공급자 키** | 카카오·네이버·구글·애플 버튼이 **비활성**으로 남는다 | 각 플랫폼 개발자 등록 |
| **결제사 실계약** | 분할 결제·보증금·멤버십이 **실제 돈을 못 움직인다** | 토스페이먼츠 |
