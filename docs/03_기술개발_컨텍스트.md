# 03. 기술·개발 컨텍스트

> 개발 산출물 작성 시 이 파일의 스택·원칙·자산을 기본값으로 사용한다. 플랫폼 버전 개발명세서는 아직 미작성(다음 작업 후보 1순위) — 아래 'MVP 도구 버전 명세 자산'은 재활용 가능한 선행 산출물이다. 앱 전략·폴더 구조·로컬 환경 상세는 05_앱개발_로컬환경_가이드.md 참조.

## 기술 스택 (기본값)
- **프론트**: Next.js 14+ (App Router), TypeScript, Tailwind CSS. 반응형 모바일 퍼스트, PWA.
- **앱(확정 전략)**: 단계적 하이브리드 — 1단계 Capacitor로 웹 래핑(카메라·푸시·스토어 입점), 2단계 전환 트리거 충족 시 Expo(React Native) 병행(packages 공용 로직 재사용). 상세·트리거는 05 문서.
- **리포 구조**: Turborepo + pnpm 모노레포. apps(web/mobile) + packages(core/api/ui/config) + supabase(migrations). 도메인 로직(룰 엔진·프롬프트·가격 계산)은 반드시 packages/core에 격리.
- **백엔드**: Next.js Route Handlers(서버리스) → 거래량 증가 시 워커 분리 검토.
- **DB·인증·스토리지**: Supabase (PostgreSQL + Auth + Storage). RLS로 사용자 격리. 소셜 로그인 카카오(주)+이메일.
- **AI**: Claude API (claude-sonnet-4-6). 낮은 temperature, JSON 스키마 강제 출력.
- **결제**: 토스페이먼츠 (건별·이용권). 에스크로는 초기 PG 에스크로 서비스 활용 → 거래량 확보 후 전자금융업 라이선스 검토.
- **배포·모니터링**: Vercel, Sentry, 자체 이벤트 로깅.
- 사용자 개발 환경: Windows/CMD. Python 보조 스크립트는 ASCII-only 소스 원칙.

## 개발 불변 원칙
1. **개인정보**: 계약서 원문 파일은 분석 완료 즉시 삭제(즉시+일배치 이중 파기). AI 전달 전 마스킹(주민번호·전화·계좌 정규식+NER, 이름은 신랑/신부/사업자 치환). DB에는 구조화 결과만 저장. Storage는 비공개 버킷+서명 URL(10분).
2. **할루시네이션 차단**: AI가 인용한 원문(quote)이 추출 텍스트에 실존하는지 정규화 후 부분일치 90%+ 대조. 불일치 finding 폐기 후 재시도(최대 2회). 근거(basis) 없는 red 판정 금지.
3. **법적 고지**: 모든 AI 검토 결과에 "참고 정보이며 법률 자문이 아님" 고정 노출 + 근거 조항(표준약관·소비자분쟁해결기준) 병기.
4. **기준 버전 관리**: 표준약관·분쟁해결기준·검출 룰은 rule_ver로 버전 관리, 리포트에 어떤 버전 기준인지 기록.
5. **신뢰 원칙의 제품 반영**: 검색·노출 순위에 유료 광고 요소 금지. 순위 결정 요소(가격·후기·이행 데이터)를 공개 가능한 로직으로 유지.

## AI 분석 파이프라인 (계약서 검토 — 확정 설계)
수신(PDF/이미지, 다중, ≤20MB) → 추출(PDF 텍스트 / 스캔·사진은 Claude 비전) → 마스킹 → 분석(컨텍스트: 표준약관 전문+분쟁해결기준+검출 룰 20종 prompt_fragment+추가금 사전 / JSON 스키마 출력) → 검증(스키마+인용 대조) → 저장·원문 파기.

출력 스키마:
```json
{
  "summary_score": 0-100,
  "findings": [{
    "clause_id": "", "quote": "원문 인용 ≤200자",
    "risk": "red|yellow|green", "basis": "근거 기준 출처",
    "explain": "쉬운 설명 ≤300자", "negotiate_tip": "≤200자"
  }],
  "missing": [{ "rule_code": "", "title": "", "why": "" }]
}
```

## MVP 도구 버전 명세 자산 (재활용 가능)
도구 단독 버전('웨딩체크') 개발명세서 v1.0에서 확정했던 것 — 플랫폼 버전 명세 작성 시 소비자 기능 파트에 흡수:
- 기능: F-01 회원/인증, F-02 AI 계약서 검토(검출 룰 20+종: 위약금 기준·환불·플래너 교체 통지·추가비용 명시·청약철회·지연배상·관할 등), F-03 최종 지불액 시뮬레이터(추가금 사전 30+ 항목), F-04 위약금 계산기(룰 엔진, AI 불사용), F-05 지역 적정가 비교(참가격+사용자 인증 견적), F-06 결제, F-07 관리자(룰·사전 CRUD, 품질 모니터링).
- 데이터 모델: users / documents(파일 경로 미저장) / reports(findings jsonb, share_token) / estimates / price_stats(p25·p50·p75) / penalty_rules / detect_rules / payments / feedbacks.
- 품질 수용 기준: 검증셋(실계약서 30건: 대행 15·예식장 8·스드메 7, 전문가 라벨) red 정밀도 90%+, 인용 일치율 98%+, 분석 p90 3분 이내, 파기 검증 잔존 0건.

## 플랫폼 버전에서 추가로 명세해야 할 영역 (미작성)
- 공급자(업체) 어드민: 상품·재고(타임/슬롯) 등록, 다이내믹 프라이싱 룰, 예약 파이프라인, 정산.
- 컴플라이언스 모듈: 고시 요구 포맷 변환·출력(홈페이지/참가격 게시용, 계약서 표지).
- 거래 레이어: 표준 전자계약 체결 플로우, 에스크로 상태 머신(계약금→중도금→이행 확인→잔금), 분쟁 조정 절차.
- AI 에이전트 확장: 검색 챗 → 실행형(투어 예약 대행, 일정 충돌 감지, 지출 자동 기록, 리스크 브리핑) 도구 호출 설계.
- 검증 후기: 계약 검증 배지, 추가금 실발생 구조화 필드.
- 플래너 마켓: 프로필·매칭·컨설팅비 결제·리베이트 프리 인증.

## 사용자 기존 기술 자산 (참고)
Python(openpyxl, python-docx), Node.js(docx), Firebase(대시보드 운영 경험), Next.js+Supabase(사주 SaaS 프로젝트 경험), 표준 배포 인프라(Vercel/Qshop) — 초기 개발을 직접 리드 가능한 풀스택 역량.
